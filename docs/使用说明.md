# 使用说明

## 1. 项目目标

这个项目把你现在在用的两段流程整理成了一个独立仓库：

1. 先把原始 GWAS summary statistics 标准化成统一格式。
2. 再把标准化后的 exposure 和 outcome 送入 `TwoSampleMR` 流程做单暴露单结局 MR。

## 2. 核心脚本

- [scripts/gwas_standardizer.py](/home/ding/MR_GWAS_Pipeline/scripts/gwas_standardizer.py)
  - 负责标准化、QC、canonical 位点 ID 生成
- [scripts/format_tsmr.py](/home/ding/MR_GWAS_Pipeline/scripts/format_tsmr.py)
  - 负责把 `data/standardized` 中的文件转换为 exposure 或 outcome
  - exposure 模式下会先按 P 值和可选区域筛选，再调用 PLINK clump
- [scripts/annotate_eaf_from_frq.py](/home/ding/MR_GWAS_Pipeline/scripts/annotate_eaf_from_frq.py)
  - 负责在标准化后，用 1KG `.frq` 和原文件 `MAF` 为缺失 `EAF` 的行做定向注释
- [scripts/mr_format_and_clump.R](/home/ding/MR_GWAS_Pipeline/scripts/mr_format_and_clump.R)
  - 保留为兼容入口，可读取旧 MR raw 或 standardized 输入
- [scripts/MR_single_pipeline.R](/home/ding/MR_GWAS_Pipeline/scripts/MR_single_pipeline.R)
  - 负责 `harmonise_data()`、`MR-PRESSO`、`mr()`、`RAPS` 和出图

## 4. 推荐工作流

### 第一步：安装 Python 依赖并准备 R 包

```bash
cd /home/ding/MR_GWAS_Pipeline
bash bin/bootstrap.sh
```

R 包请根据 [config/r_packages.txt](/home/ding/MR_GWAS_Pipeline/config/r_packages.txt) 自行安装。

### 第二步：保存原始 GWAS 文件

建议把下载的原始 GWAS 文件放进：

```text
data/Org/
```

这样项目结构会更清楚，交互模式下输入路径也会优先指向这个目录。

### 第三步：标准化原始 GWAS

先把原始 GWAS 写成标准化中间表，建议放在 `data/standardized/`：

```bash
bash bin/standardize_gwas.sh \
  --non-interactive \
  --input /path/to/gwas.tsv.gz \
  --output data/standardized/GWAS.tsv.gz \
  ...
```

如果不提供 `--output`，脚本会把文件写到 `STANDARDIZED_OUTPUT_DIR`。

### 第四步：如果只有 MAF，先补充 EAF

先从 1KG bfile 提取 `.frq`：

```bash
bash bin/build_1kg_frq_reference.sh
```

默认输出在：

```text
data/reference/g1000_eur_colon.frq
data/reference/g1000_eur_colon.frq.tsv.gz
```

然后对标准化 GWAS 做 EAF 注释：

```bash
bash bin/annotate_eaf.sh \
  --non-interactive \
  --input data/standardized/GWAS.tsv.gz \
  --frq data/reference/g1000_eur_colon.frq.tsv.gz
```

默认行为是替换原标准化文件，同时生成三个审计文件：

- `*.eaf_matched.tsv.gz`
  - 仅包含 `BIM_ID` 匹配到 1KG `.frq` 的行
- `*.eaf_frequency_diff.tsv.gz`
  - 记录 `EAF_1KG` 与 `EAF_FROM_MAF` 差异超过阈值的位点，默认阈值 `0.01`
- `*.eaf_annotation.log`
  - 记录总行数、缺失 EAF 行数、匹配到参考的行数、成功注释行数和频率差异行数

注释逻辑：

- 如果 `EAF` 原本有值，保留原值
- 如果 `EAF=NA` 且 `MAF` 有值，并且 `BIM_ID` 能匹配 1KG `.frq`
  - `EFFECT_ALLELE == 1KG A1`: `EAF_FROM_MAF = MAF`
  - `EFFECT_ALLELE == 1KG A2`: `EAF_FROM_MAF = 1 - MAF`
  - 主列 `EAF` 使用 `EAF_FROM_MAF`
- `EAF_1KG` 单独记录用 1KG `MAF` 定向到 `EFFECT_ALLELE` 的频率
- 匹配不到 reference 或等位基因对不上时，`EAF` 仍然是 `NA`

如果不想替换原文件，可以加：

```bash
--no-replace-input --output data/standardized/GWAS.eaf_annotated.tsv.gz
```

### 第五步：从 standardized 生成 exposure 或 outcome

同一个 `data/standardized/GWAS.tsv.gz` 可以重复转换成 outcome 和 exposure。

```bash
bash bin/format_tsmr.sh \
  --non-interactive \
  --input data/standardized/GWAS.tsv.gz \
  --output data/out/GWAS_outcome.csv \
  --role outcome \
  --phenotype GWAS
```

```bash
bash bin/format_tsmr.sh \
  --non-interactive \
  --input data/standardized/GWAS.tsv.gz \
  --output data/exp/GWAS_exposure.csv \
  --role exposure \
  --phenotype GWAS \
  --clump-r2 0.1 \
  --clump-kb 500 \
  --clump-p1 5e-8
```

如果 exposure 只需要在某个基因/染色体区间内 clump，可以加：

```bash
--region 1:55000000-56000000
```

如果不加 `--non-interactive`，`format_tsmr.sh` 会交互式询问 role、phenotype、样本量、是否按区域筛选和 clump 参数。

### 第六步：运行 MR

```bash
bash bin/run_mr.sh EXPO HF
```

其中：

- `EXPO` 对应 `data/exp/EXPO.csv`
- `HF` 对应 `data/out/HF.csv`

## 5. 输出说明

### 标准化输出

MR-ready 输出里最关键的是三列：

- `SNP`
  - 实际存的是 `bim_id`
  - 用于 `clump_data()` 和后续 `harmonise_data()` 匹配
- `variant_id`
  - `CHR:POS:A1:A2`
  - `A1/A2` 按字典序排序
- `rsid`
  - 注释信息

标准化 TSV 还会额外保留：

- `EFFECT_ALLELE` / `OTHER_ALLELE`
  - `beta` 实际对应的效应方向
- `EAF` / `MAF`
  - 缺失值显式写为 `NA`
- `EAF_1KG` / `EAF_FROM_MAF` / `EAF_ABS_DIFF`
  - 仅在运行 `annotate_eaf.sh` 后出现，用于记录 EAF 注释和频率差异

### MR 结果输出

每次分析会在 `results/<exposure>_<outcome>/` 下生成：

- `report.txt`
- `mr_results.txt`
- `iv_table.txt`
- `heterogeneity.txt`
- `pleiotropy.txt`
- `scatter.png`
- `funnel.png`
- `leaveoneout.png`

## 6. 已知事项

### 标准化边界

- `Mode C (A1/A2)` 必须明确告诉脚本效应值对应 `A1` 还是 `A2`，`Unknown` 不再支持。
- 如果输入频率列是 `MAF` 而不是效应等位基因频率，标准化脚本不会强行把它转成 `EAF`；标准化后可运行 `annotate_eaf.sh`，用 1KG A1/A2 为原文件 `MAF` 定向。
- 标准化脚本本身不做 strand flip、回文位点消歧和方向修正。
- 因此更适合已经明确提供 `effect allele / other allele` 或已知 `A1/A2` 方向的数据。

### R 包管理

项目不再自动安装 R 包，只维护一个清单文件 [r_packages.txt](/home/ding/MR_GWAS_Pipeline/config/r_packages.txt)。

### 运行时间

- 标准化全量 GWAS 时，主要耗时来自文件读取、QC 和压缩写出。
- MR 步骤里最慢的是 `MR-PRESSO`，IV 越多越慢。

### R 版本警告

当前机器默认 `Rscript` 是 `4.3.1`，而你的用户库目录是 `/home/ding/R/4.4.1_MR`。现在实际可运行，但可能会看到 package build version warning。这类 warning 不影响当前已验证过的流程运行。
